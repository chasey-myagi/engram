01 / POSITIONING

是什么 · 凭什么不是 RAG

三个既有范式各缺一层:RAG 缺蒸馏层(召回的是原始切片,真假和出处要 agent 自己判)、Wiki 缺原子化(给人读的叙述,机器要重新解析)、知识图谱缺出处与置信(边是二元的有/无)。Engram 把缺的那层补成内核约束。

一句话:RAG 是 agent 去图书馆借书(每次重新找、读、判真伪,书架一成不变);Engram 是 agent 自己的第二大脑 —— 召回即是"主谓宾事实 + 强制出处 + 置信度"的原子,拿来即用、即可追溯,且边用边长、越用越准。

02 / THREE LAYERS

三层模型 · 绝不塌缩

raw source(不可变证据)→ claim(蒸馏事实,机器消费)→ view/page(组织视图,人读)。RAG 的原罪正是把 raw chunk 直接当检索单元 —— 没有中间这层 claim。三层各有不可动摇的不变量。

03 / THE LIFE OF A CLAIM

一条事实的一生

claim 是 Engram 的心脏,也是唯一召回单元。它把原文里一段话蒸馏成一条自包含、可独立判真伪的事实:带强制出处、带动态置信、带稳定逻辑身份(lineage)、带 supersede 链。它进库后并非一成不变 —— 被校验、被印证、被质疑、被时间侵蚀,直到被新版本取代。

04 / INGESTION

知识怎么进来

raw 是异构、多模态、持续涌入、互相矛盾的证据池,不是一次性导入。来源按权威分级(连续、可被消费方覆盖),按形态分类(决定怎么读)。进来后不做机械 chunk,而是 distiller agent 读懂 → 蒸馏成带强制出处的 claim。矛盾是一等公民 —— 两条都留,落 contradicts 边,由置信度和时效裁决采信谁。

05 / CONSUMER CONTRACT

agent 怎么用它

任何外部 agent 通过统一的 Consumer SPI 接入,既读(检索 claim 完成任务)也写(把任务中提炼的新事实 append 回库)。两条铁律:乐观写入(带齐出处即落,不阻塞 agent loop)、悲观消费(过动态置信门才采信,否则只当线索回原文核验)。读写经 confidence 真正耦合成闭环 —— 被反复证明有用的事实自然升信。

一致性裁定 · adapter 的两层能力
配置态(主编在策展产品的 Standards 页设权重 / 门限 / 半衰期)与请求态(adapter 在单次检索里只能单调收紧)是两层、两类操作者:前者是人定标准、影响"内核默认基线",后者是消费策略、只能在基线之上更保守。二者不冲突 —— 请求态永远不能放宽配置态定下的基线。
06 / TRUST & IMMUNITY

信任模型 + 免疫系统

激进写入安全的前提是免疫力 ≥ 写入力。治理沿"写入 → 消费"时间轴纵深布防:越往前越轻(库层约束),越往后越重(LLM 推理)。语义判断只在事后 —— 因为"可追溯"是客观廉价二值的,适合同步硬门;"对错"是主观昂贵且随时间变的,必须搬到事后巡查(Wikipedia 先发后审 / Git revert 不 rewrite)。

两条确定性规则
冲突收敛优先级(确定性,可回归测试):人裁 > 取代关系(supersede) > 时效(as_of 新) > 来源权威 > 印证数。机判把握不足则升级人。 自我调速:GovernanceController 每分钟比对五指标(队列积压 / entailment 拒绝率 / 冲突待裁 / 免疫滞后中位数 / 误隔离率)——写入跑赢免疫就自动抬高 D2 门(更多沉影子区),免疫追上再滞回放松。人只在裁冲突 / 赦免 / 定标准三处介入。
07 / CURATION

人即主编

agent 是主要作者也是主要读者,人退到主编位。Engram 自带一个独立 Web App(Studio),不依附任何业务前端。主编不逐条写事实,只做四件机器做不了的事:定标准 · 审异常 · 纠错 · 裁冲突。一切写入走 append(永不覆盖),人的裁决以"最高单位权重因子"进入 confidence —— 人不直接写 status,只投因子,由门限决定落到哪个态。

08 / ASSEMBLY

总装 · 编队 · 架构

Engram 自带一支按职责切分的内部 agent 编队,不是单个全能 agent —— 因为裁判必须独立于运动员:写事实的 agent 会系统性相信自己刚写的东西(RAG 时代"幻觉自我印证"的根源)。校验与裁决在 session 上下文 + DB role 两层物理独立于蒸馏,否则悲观消费那道门形同虚设。

09 / ORCHESTRATION & LOOPS

编排 · 每个 agent 的循环

要不要一个 meta-agent 统管编队?裁决:控制面主干保持确定性,LLM 推理降级为旁挂式 Advisor。核心是能力与权力分离 —— Advisor 持推理能力但零写权限,只产建议;确定性的恒温器 + 验收门持决策权力但不推理。谁都不能既推理又拍板。失效则静音 Advisor、退回三层主干,零数据损坏。

维度恒温器 GovernanceControllerAdvisor 建议器
处理对象量(五个标量指标)质(claim/relation 语义内容)
决策性质阈值比较,纯函数开放式语义推理
写 store 权限有(封闭枚举动作)零(只读物 advisory.*)
落地路径直接生效必过确定性验收门
可复现同输入同输出,可单测不可复现 → 故不进控制回路
失效降级维持当前闸门(安全态)静音 event,退回三层

至于这些 agent 是 one-shot LLM 还是真 agent loop —— 不是审美选择,是任务结构的函数。判据一句话:执行前状态空间是否已收敛。单步可枚举的映射(抽取判定、分类、转换)是函数;只有"下一步做什么依赖这一步看到了什么、且分支无法预先穷举"时,才需要 perceive→reason→act→observe 的反馈环。第二道闸是成本:高频 + 低语义 → 必须确定性;低频 + 高语义 → 可负担有界 loop。

一句话 能力下沉(loop 持语义能力)、权力收口(全局动作归恒温器 + 验收门)。五工种都是数据面局部决策者,即便 Distiller/Arbiter 是真 loop,写权限也封闭在各自职责枚举内(Distiller 只写 draft、Arbiter 只动单对 status),没有任何一个持有全局闸门。
10 / EVALUATION

评测 · 怎么算够好

对自养 KB,"够好"不是单个准确率。而且端到端 benchmark 会掩盖是哪一环坏的 —— 所以是一个测试金字塔:每个 agent 的组件级 benchmark(定位)+ 控制面仿真 + 系统级端到端。命门三件别人不测的事:confidence 校准(校准不了,悲观消费那道门就是假的)、免疫效能(红队注入测自纠错)、纵向越用越好(agentic memory 唯一卖点,测不出来就只是慢 RAG)。

层测什么形态
L1 · 组件级(每个 agent 一套 golden set)单个 agent 在隔离 session 里的准确率 —— 定位是哪一环坏、换模型可快速回归单元/准确率测试
L2 · 控制面(恒温器)灌入"写入突增/免疫滞后拉长"负载轨迹,看是否收敛、不振荡、不超调控制系统仿真(非准确率)
L3 · 系统级(端到端)八维度 + 校准 + 纵向 + 下游 A/B,经同一套 Consumer SPI 接入集成测试 / 元免疫层
L1 · 每个 agent 的组件 benchmark

每个 agent 的 benchmark 不看总 F1,而是盯住"那个会污染知识库的方向" —— 和免疫系统"宁可错杀不放过"的偏置一致。每张表与该 agent 的循环规格一一对应。

北极星 · 红蓝对抗(future,非现在做)

评测的远期形态:把"元免疫层"从静态金标升级成动态对抗 —— 红队 agent 造题、蓝队(就是 prod consumer agent 本体)答题、裁判 Arbiter 判分、失败按根因回流成增长 + 下一版更难的题。它是北极星不是当前里程碑,但有两条铁律现在就得立死。

现在就立的两条承重墙红线
① 考卷本身也要被验真(题=毒株,不是真值):带 reward 的造题 agent 是最强真值污染源,红队的题必须先过"题的免疫流水线"才能晋升 golden。② ELO/胜负率严禁进纵向趋势和校准 g:看着像"越用越好"却与命门⑧(ECE↓)无因果,喂进飞轮 = Goodhart。
近期两件事(<1 周,真能过 Feature Gate,先做这个)
① 给 prod 消费埋 report_usage 埋点 —— 被动收"驳回/纠正/采纳",攒 2-4 周得到真实失败分布(红蓝最高保真题源的真实燃料,几乎零工程)。② 人工写 10-20 道 L5 缺口题(库里本无答案,正解=门后零召回+记缺口)—— 测零幻觉诚实性,当前单标量 benchmark 最大盲区。红蓝联赛/市场/自指全部 defer 到地基(confidence 变成可校准概率)跑通之后,顺序见 §12。
11 / KEY ALGORITHMS

核心机制 · 把"待定义"补成可施工

三审点名了四个"被反复引用却没定义"的硬阻塞算法。这里逐一补成能照着实现的定义。其中 confidence 归一映射 g 是命门 —— 它一天不就位,§10 的校准、§6 的悲观消费门、整套"信得慢"全是空中楼阁(当前 prod 还是 min(1, 来源数×0.3) 五档离散,不是概率)。

机制方法(起步 → 进阶)输出危险 / 风险
confidence 归一 graw=Σwᵢ·factorᵢ → temperature σ(raw/T) → isotonic 非参单调conf∈[0,1] 概率★ raw 须先连续化,否则 g 无意义
embedding对 claimText(蒸馏事实,非 raw chunk)生成 ~768–1024 维,commit 时算,pgvector + HNSW召回 + 去重底座模型升级→历史向量不可比,需全量重嵌入 + 版本锚
lineage 匹配两阶段:① embedding 近邻 + subjectKey 召候选 ② 确定性规则 + 灰区 one-shot LLM同一(共 lineageId)/ refines / contradicts / 无关object 语义等价边界(≥4K vs 至少4K)灰区必走 LLM + metamorphic 自检
独立来源判定独立 ⟺ id≠ ∧ hash≠ ∧ 无 derived_from 血缘 ∧(可选)origin≠印证只数独立 supports 源隐性同源(都抄自同一原始未记血缘)→ 近似哈希 + 偶尔人工
核心公式(伪代码)
# confidence 归一(g)—— 命门
raw  = Σ wᵢ·factorᵢ           # 七因子线性合成,w=配置态(主编设,可解释语义权重)
conf = g(raw)                # g 单调;起步 temperature: conf=σ(raw/T);进阶 isotonic 非参
# g 由 observed correctness 校准拟合(§10 三环),与 w 分离:w 答"为什么信",g 答"数值=真实概率"

# 独立来源判定(印证去重)
independent(s1,s2) = s1.id≠s2.id ∧ s1.hash≠s2.hash ∧ ¬derivedChain(s1,s2)
corroboration = |{ 独立 supports source }|     # 不是 |provenance| —— 防同源刷印证

# lineage 同一事实判据
same_fact(a,b) ⟺ a.subject≡b.subject ∧ a.predicate≡b.predicate
               ∧ object_equiv(a.object,b.object)   # 数值/单位归一 或 语义等价(灰区→LLM)
12 / ROADMAP

推进路线 · 从设计稿到北极星

三审最锋利的一句:"最该先回答的不是红队怎么造题,而是 confidence 什么时候从来源计数器变成可校准的概率"。在地基跑通前,所有八维度数字都是对不存在系统的幻觉。所以推进严格地基优先,每阶段有可观测验收和解锁下一阶段的前置门 —— 没过门不许跳级。

一句话排序 先把 confidence 变成可校准的概率(Phase 0)+ 埋 report_usage / 写 L5 缺口题(Phase 1,<1 周) —— 这是唯一同时过 Feature Gate 1(真实痛点)和 Gate 4(近零成本)的起步。红蓝联赛 / 市场 / 自指全部 defer,等地基跑通 + 证明朴素方案不够用再谈。
13 / OPEN & CROSS-CUTTING

未决与横切 · 诚实清单

四个曾"被引用却未定义"的硬阻塞算法已在 §11 补成可施工定义;红蓝对抗已收敛为 §10 的北极星 + 近期两件事;推进顺序见 §12。这里只留真正还悬着的:横切关注点 + 必须由人拍板的治理红线。
