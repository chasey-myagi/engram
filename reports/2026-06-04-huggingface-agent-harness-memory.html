1. AMA-Bench

类型：HF dataset + benchmark stack
置信度 5/5

这是当前最完整的 Hugging Face 记忆 benchmark 栈之一：HF dataset 卡明确给出 网站、GitHub、leaderboard、paper 四个入口；GitHub README 则把方法接口收敛成 memory_construction 与 memory_retrieve 两段式，且 repo 显示 2026 年 3 到 5 月连续放出 dataset、leaderboard 与 AMA-Agent code。

为什么重要：它天然对应 harness-pi 的“确定性 orchestration + per-run terminal result”与 Engram 的“memory object / retrieval seam”。

Recency：HF dataset 发布于 2026-02；GitHub README 记录 2026-03 repo 启动、2026-05 论文被 ICML 2026 接收。

Caveat：默认接口更偏“从 trajectory 构建 memory object”，还没直接约束 provenance 或 claim 级写治理。

HF Dataset GitHub HF Paper arXiv

2. AMA-Bench Leaderboard

类型：HF Space / operational eval surface
置信度 4.5/5

与很多只发论文的 benchmark 不同，AMA-Bench 同步给了 Hugging Face Space 形式的 leaderboard。 这让它不只是“一个 dataset”，而是一个已经具备提交与对比路径的公共评测表面。

为什么重要：对本地最有价值的不是排行榜名次，而是它迫使 benchmark 设计走向可提交、可复验、可比较的标准接口。

Recency：HF dataset 卡与 GitHub README 都记录该 leaderboard 于 2026-03 上线。

Caveat：Space 本身是评测入口，不提供 claim/provenance 语义；需要和主 benchmark 配套理解。

HF Space HF Dataset GitHub

3. MemoryArena

类型：HF paper + HF dataset + project site
置信度 4.5/5

MemoryArena 把评测中心从“记住长上下文”推进到“跨 session 的 interdependent subtasks”。 项目主页公开列出 Stanford / UCSD / UIUC 等作者背景，并直接连到 HF dataset 与 GitHub。 HF dataset 以五个子集组织任务，包含 bundled shopping、progressive search、group travel planner 与 formal reasoning。

为什么重要：它最贴近 harness-pi 的 resume / fan-out / reanswer 闭环，也最贴近 Engram 想做的“越用越准”而非单次 recall。

Recency：HF paper 发布于 2026-02；HF dataset 现有 12 likes，项目页和数据页都在线。

Caveat：复现栈比 AMA-Bench 轻一些，repo 和 leaderboard 信号没有那么强，适合作为任务形状参考，不一定先做主 benchmark。

HF Paper HF Dataset Project Page GitHub

4. MemoryAgentBench

类型：HF paper + HF dataset + GitHub benchmark
置信度 5/5

这是目前最清楚地把 memory 能力拆成四个 competency 的 HF benchmark： Accurate Retrieval、Test-Time Learning、Long-Range Understanding、Conflict Resolution。 HF dataset 卡写明 MIT license、四个 split、最近月下载量 24,622，并给出公开 GitHub 代码仓库。

为什么重要：如果 AMA-Bench 适合系统级 eval，MemoryAgentBench 更适合做 component eval，把 recall / update / contradiction 各自打散测。

Recency：HF paper 发布于 2025-07；dataset 卡记录 2025-09 到 2025-10 的多次数据修订。

Caveat：更偏受控增量交互，不如 MemoryArena 那样贴多 session 真实任务闭环。

HF Dataset HF Paper GitHub arXiv

5. OpenJudge Agent Memory Graders

类型：HF dataset + GitHub eval framework
置信度 5/5

OpenJudge 在 HF dataset 卡里直接把 agent 维度拆出 Memory (Accuracy / Retrieval / Preservation)，并给到每个任务目录都有 evaluate_*.py 的复现实验脚本。GitHub README 进一步说明它是 “Holistic Evaluation, Quality Rewards”的统一 grader 框架，覆盖 agent lifecycle、tool、memory、trajectory。

为什么重要：这最适合借给 harness-pi 做 grader 层，而不是自己从零造 judge harness。

Recency：HF dataset 最近两周仍有 commit；GitHub README 标注 2026-04 新增 skill graders，站点仍在快速扩张。

Caveat：它是 grader 框架，不是 domain truth；如果把 judge 当 ground truth，会把 Engram 的“题先验真”红线踩穿。

HF Dataset GitHub HF Script

6. AlphaEval

类型：HF paper + GitHub production benchmark
置信度 5/5

AlphaEval 不是 memory benchmark，但它对 agent harness 很关键。 GitHub README 明确写出 94 个来自 7 家公司的任务、6 个 O*NET 域、多范式评测与 Docker sandbox， 并强调它评估的是完整 agent product 而不只是模型。仓库是 MIT license。

为什么重要：它为 harness-pi 提供了“评 agent product 而不是评模型”的现成论证，也适合给 Engram 做后续生产型 benchmark 包装。

Recency：HF paper 发布于 2026-04；GitHub 仓库同样是 2026 新项目。

Caveat：不是记忆专用 benchmark；直接借来测 Engram 会漏掉 claim / provenance 特有失效模式。

HF Paper GitHub arXiv

7. A-MEM

类型：HF paper + open-source memory system
置信度 4/5

A-MEM 的亮点不在 benchmark，而在 memory shape：它把 Zettelkasten 风格的动态索引、链接、 note 演化与 agent 决策绑到一起。GitHub README 明说系统仓库负责 memory system 本身， 论文复现实验则在另一个评测仓库里。

为什么重要：它是目前最接近 Engram “claim network / relation / evolution”气质的开源记忆系统之一。

Recency：HF paper 发布于 2025-02；主仓仍在线且安装/使用说明完整。

Caveat：system repo 与 evaluation repo 分裂，工程可读性可以，严格复现实验则要多走一步。

HF Paper System Repo Eval Repo arXiv

8. AtomMem

类型：HF paper + official code
置信度 4/5

AtomMem 把 memory management 重写成可学习的 CRUD 原子操作决策问题，而不是固定 pipeline。 GitHub 搜索结果显示这是 official code，仓库有 25 commits，README 给了环境、依赖和数据准备路径。

为什么重要：它为 Engram 的 append / retrieve / supersede / delete-like quarantine 操作空间提供了训练式视角，而不是纯手写策略。

Recency：HF paper发布于 2026-01，GitHub 最近一周仍可见。

Caveat：benchmark 主要还是长上下文 QA 族，不是完整 agent runtime；拿来借动作空间比借总架构更合适。

HF Paper GitHub arXiv

10. MATPO-14B

类型：HF model + rollout artifacts
置信度 4/5

这是少数直接在 Hugging Face 上可拿 checkpoint 的“planner/worker 角色分化”模型工件。 Model card 明示 Apache-2.0，给出 GAIA / FRAMES / WebWalkerQA 结果，并说明训练脚本与 rollouts 已开放， 同时给出基于 veRL 的训练依赖。

为什么重要：如果想做“角色分工来自 policy 训练，而不只是 runtime fan-out”，它是这轮候选里最容易直接试的 HF 模型对象。

Recency：model card 记录 2025-10 发布 checkpoints、rollouts 和 code。

Caveat：它偏训练研究，不是现成 harness；对本地更像对照组或实验模型，而不是直接拿来当 runtime。

Deep Dive

首选深挖：AMA-Bench

选择理由：不是它“最酷”，而是它在目前候选里同时满足 HF 主发现面、公开 dataset、公开 repo、公开 leaderboard、方法接口明确、能直接对接本地 runtime seam 这六个条件。

它是什么

AMA-Bench 是面向 agentic trajectory 的长时记忆 benchmark。HF dataset 卡显示它公开了 208 行测试数据、MIT license、完整 quick links；arXiv 摘要则把问题定义为“连续 agent-environment interaction 的记忆”，并提出 AMA-Agent 作为参考方法。

核心方法与实现抓手

GitHub README 最值得借的不是具体模型，而是统一接口：memory_construction(traj_text, task) 与 memory_retrieve(memory, question)。这把“构建 memory”和“按问题取证”拆成两个可替换阶段， 非常接近本地已经存在的两条缝：harness-pi 的 session/controller 运行时骨架，和 Engram 的 append_claim / recall_claims Consumer SPI。

证据：GitHub README 明确写出 two-stage interface 和默认评测目录结构。

推断：这意味着本地完全可以先不改 kernel，只做一个 benchmark adapter 层试接。

评测主张

arXiv 摘要声称：现有 memory systems 在 AMA-Bench 上普遍欠佳，主要缺 causality 与 objective information； AMA-Agent 以 causality graph + tool-augmented retrieval 取得 57.22% 平均准确率，比最强 baseline 高 11.16%。

证据：这来自论文摘要，不是我复跑后的确认。

推断：如果这个结论成立，Engram 最应避免的是“只做相似度检索的 memory facade”。

源码质量与复现性

这套东西比大多数“只有论文页面”的对象扎实：HF dataset、HF space、GitHub、项目主页都在线； GitHub README 记录 2026-03 到 2026-05 的连续发布；repo 有 MIT license、requirements、src、scripts、 configs、evaluation 说明和提交 leaderboard 的入口。

判断：足以列入“可做本地 follow-up”的高优先级，而不只是“值得关注”。

AMA-Bench 元素 映射到 harness-pi 映射到 Engram
Trajectory-first memory construction AgentSession / RunSummary / session store 输出可直接喂构建阶段 构建阶段不要产 opaque summary，优先产 claim + provenance + relation
Question-time retrieval seam 可做 controller 级评测适配器，不必改 kernel 直接映射到 recall_claims(query, ctx)
Causality-aware memory 适合补在 orchestration / replay / event lineage 上 适合补 relation 与 contradiction / supersede 边，而不是只存 embedding
Public leaderboard 利于形成稳定 submission harness 可把 claim-graph 方案与 summary baseline 做公开对比
为什么它优于 MemoryArena 成为首选

MemoryArena 在“多 session + interdependent subtasks”上更像最终目标； 但 AMA-Bench 的公开工件更完整，接口更明确，复现实验门槛更低，更适合先拿来搭第一版本地 eval adapter。

主要局限

1. 两段式接口会默认你把 memory 当成独立对象处理，天然弱化了 provenance / human governance。
2. 数据集只有 test split，适合 benchmarking，不适合拿来做训练闭环。
3. 开放式 QA 仍可能把 judge/metric 设计带回瓶颈。

对本地最可复用的三个点

1. 把 benchmark seam 固定在 build/retrieve 两段，而不是散在 runtime 内。
2. 让 leaderboard / submission 约束方法接口。
3. 用真实 agent trajectories 而不是静态书本段落做主数据面。

对本地不该照抄的点

1. 不要把 Engram memory object 退化成无 provenance 的摘要缓存。
2. 不要把 benchmark judge 直接当真值来源。
3. 不要为了适配 benchmark 而牺牲 claim-level 事务边界。

Next Steps

建议的本地后续动作

这三步都能在不改大架构的前提下推进，而且每一步都能留出可验证工件。

1. 做一个 AMA-Bench adapter spike

目标不是追分，而是把 AMA-Bench 的 two-stage interface 映射到本地： stage A 用 harness-pi 跑 trajectory 处理， stage B 调 Engram 的 recall_claims。

2. 做 claim-graph vs summary baseline

最少两条 baseline：一个只做摘要记忆，一个走 claim + provenance + relation。 先比较 contradiction / long-horizon retrieval / mustVerify 行为，不必一开始追绝对分。

3. 把 OpenJudge 接到 grader 层

不把它当真值库，而是当自动 grader runner。这样可快速补一个“memory behavior regression” 套件，服务本地 loop，而不是再造 judge shell。

如果只选一个立即可做动作，我会选 AMA-Bench adapter spike。 原因很简单：它最容易逼出本地当前设计里“runtime state 和 durable memory state 的边界”到底够不够清楚。
